# LINEスタンプ作成支援ツール「stamp-cut」要件定義書

- 作成日: 2026-08-04
- ステータス: ドラフト(レビュー待ち)

## 1. 背景・目的

ペット(動物)や人物の写真から LINE スタンプを自作したいというニーズは多いが、実際に
LINE Creators Market へ申請するまでには以下のハードルがある。

- 被写体の切り抜き(背景透過)を写真ごとに手作業で行う必要がある
- スタンプ画像・メイン画像・タブ画像それぞれにピクセルサイズ等の細かい規格がある
- 8〜40 個の画像を規格どおりのファイル名・形式で揃えるのが面倒

本ツールは「写真をアップロードするだけで、LINE スタンプ申請にそのまま使えるアセット一式が
できあがる」ことをゴールとする。画像編集ソフトの知識がない人でも、スマホで撮った
ペットの写真から 10 分程度でスタンプ申請用 ZIP を作れる状態を目指す。

## 2. 想定ユーザー・ユースケース

| ユーザー | ユースケース |
|---|---|
| ペットの飼い主(メインターゲット) | 愛犬・愛猫の写真からスタンプを作り、家族や友人と使う/販売する |
| 家族・カップル | 子どもや家族の写真でプライベートスタンプを作る |
| 個人クリエイター | 手持ちの写真素材から手早くスタンプの下地を量産する |

前提とするリテラシー: 画像編集ソフトは使えないが、スマホ・ブラウザ操作はできる。

## 3. 成果物(ツールが出力するもの)

LINE Creators Market の申請規格に準拠したアセット一式。

### 3.1 LINE スタンプ画像規格(準拠対象)

| アセット | サイズ | 形式 | 備考 |
|---|---|---|---|
| スタンプ画像 | 最大 W370 × H320 px | PNG(背景透過) | 8 / 16 / 24 / 32 / 40 個のいずれか |
| メイン画像 | W240 × H240 px | PNG(背景透過) | ストアに表示される代表画像 |
| トークルームタブ画像 | W96 × H74 px | PNG(背景透過) | スタンプ一覧タブ用 |

共通制約:

- カラーモード RGB、解像度 72dpi 推奨
- 1 ファイル 1MB 以下、ZIP 全体 20MB 以下
- サイズは偶数ピクセルであること
- 被写体の周囲に 10px 程度の余白を確保することが推奨されている

※ 規格は LINE 側で改定されうるため、実装時に [LINE Creators Market 制作ガイドライン](https://creator.line.me/ja/guideline/sticker/) の最新値を確認し、サイズ等は設定値として一元管理する。

### 3.2 出力パッケージ

- `main.png`(メイン画像)
- `tab.png`(タブ画像)
- `01.png` 〜 `40.png`(スタンプ画像。選択した個数分)
- 上記をまとめた ZIP(申請画面にそのままアップロード可能な構成)
- (任意)全スタンプを並べた一覧プレビュー画像(SNS 共有・確認用)

## 4. 機能要件

### 4.1 MVP(必須)

#### F-1 画像アップロード
- 複数枚の一括アップロード(ドラッグ&ドロップ / ファイル選択。スマホはカメラロールから)
- 対応形式: JPEG / PNG / WebP / HEIC(iPhone 写真対応のため HEIC は必須)
- 1 枚あたり上限 20MB 程度。超過時・非対応形式はエラーメッセージで案内

#### F-2 被写体の自動切り抜き(背景除去)
- アップロードされた各画像から被写体(動物・人物)を自動検出し、背景を透過化する
- 白い被写体 × 明るい背景(例: 白い犬 × 白壁)のような低コントラスト画像でも
  実用精度で切り抜けるモデルを選定すること(参考画像のマルチーズが典型例)
- 髪・毛のふち(フリンジ)を自然に処理できること(アルファマット対応が望ましい)

#### F-3 手動補正
- 自動切り抜きの結果をブラシで「残す / 消す」修正できる簡易マスク編集
- 切り抜き範囲のトリミング(位置・拡大縮小)調整

#### F-4 規格準拠の自動整形
- 切り抜き後の画像を 370×320px 内に自動フィット(アスペクト比維持、偶数 px、余白 10px 確保)
- PNG 圧縮で 1 ファイル 1MB 以下に自動調整
- メイン画像(240×240)・タブ画像(96×74)は、ユーザーが選んだ 1 枚から自動生成

#### F-5 セット管理とプレビュー
- スタンプ個数の選択: 8 / 16 / 24 / 32 / 40
- グリッド表示で並び順をドラッグで入れ替え、不要な画像の削除、枚数不足の警告
- LINE トーク画面風プレビュー(白背景・ダーク背景の両方で透過の粗を確認できること)

#### F-6 エクスポート
- 3.2 の構成で ZIP を生成しダウンロード
- ファイル名は LINE の申請規則(`main.png` / `tab.png` / `01.png`〜)に自動で揃える

### 4.2 将来拡張(MVP 対象外)

- テキスト・吹き出し・スタンプ風装飾(縁取り・白フチ)の追加エディタ
- 画像の一括色調補正(明るさ・コントラスト)
- アニメーションスタンプ(APNG)対応
- 作成途中データの保存・再開(アカウント機能)
- 生成 AI によるデフォルメ・イラスト化

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| プラットフォーム | Web ブラウザ(スマホ・PC 両対応、レスポンシブ)。アプリインストール不要 |
| 性能 | 切り抜き 1 枚あたり数秒以内(目安 5 秒)。40 枚一括でも進捗表示付きで完走できること |
| プライバシー | アップロード画像はスタンプ生成以外に利用しない。サーバー処理する場合は処理後すみやかに削除(保持期間を明記)。可能ならブラウザ内完結(後述)を優先 |
| コスト | 個人利用を想定し、サーバー費用が枚数に比例して膨らまない構成を優先 |
| 対応ブラウザ | iOS Safari / Android Chrome / PC Chrome・Edge・Safari の最新版 |
| 多言語 | まず日本語のみ |

## 6. 技術構成(案)

### 6.1 背景除去の方式比較

| 方式 | 例 | 長所 | 短所 |
|---|---|---|---|
| A. ブラウザ内推論 | `@imgly/background-removal`(ISNet 系, WASM/WebGPU) | サーバー不要・画像が端末外に出ない・コストゼロ | 端末性能に依存、低スペックスマホで遅い |
| B. 自前サーバー推論 | `rembg`(U²-Net / ISNet / BiRefNet) | 精度・速度が安定、モデル選択の自由度 | GPU/サーバーコスト、画像を預かる責任 |
| C. 外部 API | remove.bg 等 | 精度が高く実装が軽い | 従量課金、外部送信の規約・プライバシー説明が必要 |

推奨: **MVP は A(ブラウザ内完結)** で開始し、精度・速度が不足するケース向けに
B をオプション追加する二段構え。プライバシー要件とコスト要件を同時に満たせる。

### 6.2 構成案(A 方式ベース)

- フロントエンド: Next.js + React + TypeScript(静的ホスティング可)
- 切り抜き: `@imgly/background-removal`(WebGPU 利用可能なら優先、フォールバックで WASM)
- 画像整形・PNG 出力: Canvas API(リサイズ・余白・偶数 px 調整・圧縮)
- HEIC 変換: `heic2any` 等でアップロード時に変換
- ZIP 生成: `JSZip`(すべてクライアント側で完結)
- マスク手動補正: Canvas ベースの簡易ブラシエディタ

## 7. 画面フロー(案)

1. **トップ**: ツール説明+「写真を選ぶ」ボタン
2. **アップロード & 一括切り抜き**: 進捗バー付きで自動処理、結果をグリッド表示
3. **個別編集**: 各画像のトリミング・マスク補正(必要な画像だけ)
4. **セット編集**: 個数選択、並び替え、メイン/タブ画像に使う 1 枚を指定
5. **プレビュー & 書き出し**: トーク画面プレビュー確認 → ZIP ダウンロード
6. **完了**: LINE Creators Market への申請手順の案内リンク

## 8. スコープ外・制約・リスク

- **審査は対象外**: LINE の審査(著作権・肖像権・ガイドライン適合)はユーザー責任。
  申請前チェックリスト(第三者の写り込み、ロゴ・キャラクター混入など)を表示して注意喚起する
- **切り抜き精度の限界**: 被写体と背景の分離が困難な写真(強い逆光、被写体と同系色の背景)は
  手動補正が前提になる。精度検証には参考画像のような「白い犬」のケースを必ず含める
- **規格変更リスク**: LINE 側の規格改定に追従できるよう、サイズ・個数・容量制限は
  ハードコードせず設定ファイルで管理する
- **人物写真の扱い**: 本人・家族以外の人物写真の利用は肖像権の問題があるため、利用規約と
  UI 上の注意文で明示する

## 9. 受け入れ基準(MVP)

1. iPhone で撮影した HEIC の犬写真 16 枚をアップロードし、全自動処理のみで
   LINE 申請規格を満たす ZIP(main / tab / 01〜16)が取得できる
2. 生成された全 PNG が「370×320 以内・偶数 px・透過・1MB 以下」を満たす
3. 白背景に白い犬の写真でも、手動補正込みで実用的な切り抜きが完成できる
4. スマホ(iOS Safari / Android Chrome)で一連のフローが完了できる

## 10. 未確定事項(要確認)

| # | 論点 | 選択肢 / 備考 |
|---|---|---|
| 1 | 提供形態 | 完全ブラウザ内(推奨)か、サーバー処理ありか |
| 2 | 対象範囲 | 静止画スタンプのみで開始か、絵文字(180×180)・着せかえも視野に入れるか |
| 3 | 装飾機能の優先度 | MVP では切り抜き+整形のみとしたが、テキスト入れを MVP に含めるか |
| 4 | 公開範囲 | 個人利用ツールか、一般公開サービス(利用規約・アカウント設計が必要)か |
| 5 | マネタイズ | 無料か、処理枚数課金・高精度モデル課金などを想定するか |
